# 0014 Ad variants, Make creative, and logo upload

**Date:** 26 October 2026. **Status:** accepted (built in Sprint 5: S5-3 variants and route, S5-4 server side, F-10 upload).

**Context.** Decisions 0011 to 0013 gave us copy sets, pictures and a renderer. S5-3 and S5-4 join them: a variant is a picture, a copy set and a layout; Make creative runs the Imagery and Copy agents and composes the variants; a person picks, discards, switches layouts and asks for new pictures or words. Rule 3 says a person approves anything that replaces creative, and rule 4 says every run is traceable. F-10 adds logo upload.

**Decision.**
- **A variant is a row, the PNG is drawn on request.** `ad_variants` keeps the picture (an image asset), the words (a paid-social or display copy set), the layout, the renderer's checks (contrast, fit, legal line, logo, fonts) and a snapshot of the kit it was drawn with (palette, fonts, brand name, and the SVG text or the PNG logo asset id). The snapshot means an ad looks the same tomorrow even if the brand's palette or logo changes, as copy sets keep their legal lines (0011). The table is append-only except `picked_at`, `discarded_at` and `layout`; the checks change only together with the layout, because they are that layout's checks. A trigger checks that the picture is an image of the same campaign and the words an ad set of the same brief version, and a partial unique index allows one current variant per picture and words.
- **`/ads/[id]` (with or without `.png`)** reads through `asUser()` and answers 404 alike for another workspace's variant, a malformed id, no session, or a variant whose picture or words are discarded. It sends `cache-control: private, no-cache` with an ETag from the renderer version, the picture's sha256, the copy set id (sets never change), the layout and the kit snapshot's hash, so a browser revalidates and gets a 304 without a drawing while nothing changed, and a layout switch changes the ETag. An in-process cache keeps the last 48 drawings. A stored variant the renderer now refuses (it passed when made, so this means a missing font file or similar) answers 422 with the reason and is logged. The route is request-time work (session and headers), never prerendered or `use cache`d.
- **Composition.** Each current picture of the signed-off version with each current ad set for the brief's first audience (paid social, and display if the brief has it), in the first layout that renders: Full bleed, then Split, then Card. A pair that refuses in every layout is reported in the run, not recorded. Sets that are new words still waiting beside their original (0011) are not composed. With several audiences, the gallery uses the first audience's three sets and says so; the other audiences' words are listed beside it. Pictures are stored as WebP (0013) and converted to PNG with sharp for the renderer.
- **Make creative** is a workflow (`creative`, not a model agent, registered in `WORKFLOWS`; runs are created with `createWorkflowRun`). It records the Imagery and Copy runs as child runs (`input.parentRunId`), runs their workflows inside its own Inngest function with prefixed step ids, both at once, then composes. Each child keeps its own trail, status and cost; the parent's trail has four system steps (read, pictures, copy, compose), and the gallery shows the parent with its children's total cost. Imagery always draws four new pictures. Copy runs only when the version has no current copy yet (S5-2's one-full-run rule); otherwise the existing sets are reused and the trail says so. The variants are composed from this run's pictures only. The outcome is `completed`; `stopped_cap` when either child stopped at the cap (what was made is kept and composed, and the error says how many ads from how many pictures); or `failed` when no ad could be made (pictures and copy that were made are kept, so a second Make creative reuses the copy). One Make creative per signed-off version while it has current ads, refused while one is running, and refused before anything is spent when the brief has no paid-social or display channel or the brand has no palette.
- **New picture** is a `creative` run in `picture` mode: one image call and its check for text, through the Imagery workflow's own draw and check functions (no redraw, so the price shown is the price paid). If it passes, a new variant on the new picture (same words, the old layout if it still renders) replaces the old one, which is discarded; the person's click is the approval. The old picture is marked discarded once no current ad uses it: a picture is shared by the ads for each of its three sets, and "New picture replaces only that image in that variant" (S5-4 #2) means the siblings keep it. A picture with text, a provider error or the cap leaves the ad as it was.
- **Words follow their copy set, and only when a person chooses.** A set is shared by the ads for every picture, so new or edited words move every current ad on that set. New words (`newWords`) start S5-2's replacement run; the replacement waits beside the original and each of its ads shows `pendingWords` until a person calls `keepWords(variantId, "new" | "old")`. Keeping the new words discards the old set and replaces each ad on it; keeping the old discards the new set. Edit words checks the copy rules (as `saveCopyEdit` will) and the fit in every layout first, so a refused edit saves nothing; then `saveCopyEdit` makes the person's set (discarding the old one, S5-2's rule) and the ads move to it. A replacement ad keeps the pick of the ad it replaces.
- **Restore** brings back a discarded ad only while its picture and words are current and the same pair isn't in the gallery again; otherwise the reason is given. An ad whose words a person discarded in the copy lists is hidden (not marked), and returns when the words are restored.
- **Estimates** for the buttons come from `prices.ts` and the configured models with typical token counts in `src/lib/creative/costs.ts`, rounded up to whole pence: New picture "about 3p", New words "under 1p" on Sonnet, Make creative about 14p in real mode (four pictures 10.6p, checks and prompts under 0.2p, copy about 3p). After the Sprint 5 review (finding 9) the Make creative button also shows its worst case, "about 14p, at most 31p": every picture redrawn (eight images, 21.2p), and every model call repaired once at its full output allowance (copy 8.3p, checks 0.4p, prompts 0.2p), with typical inputs. That is above the refined 20p, which held only for the typical run; the worst case is the figure for any check against the cap before starting. The cap still decides at call time.
- **Logo upload.** The file's contents decide what it is: a `.png` must start with the PNG signature and decode as PNG; an SVG must be UTF-8 text starting with `<svg` (after an XML declaration, comments or a doctype without entities) and pass `checkUploadedSvg`. PNG: 1 MB at most, refused above 4096 × 4096 pixels from its header before decoding, then decoded and re-encoded by sharp (no EXIF, text chunks or trailing bytes survive) at most 1024 px on its longest side, and stored as an asset of kind `logo` linked from `brands.logo_asset_id` (a trigger checks it is a PNG logo of the same brand; the composite key keeps it in the workspace). A brand has one logo: either upload clears the other kind, and a replaced PNG stays in the store, discarded. `updateBrand` keeps the stored logo when `logoSvg` is left out, and the brand editor's save no longer passes it.

**Consequences.** Every first view of an ad costs a drawing (about 0.2 to 0.3 s) on whichever server instance answers; the gallery's twelve are drawn once per instance and then answered by ETag. Ads made before a kit change keep the old kit; getting the new logo or palette into existing ads means discarding them and running Make creative again (which draws new pictures), so a free "redraw with the current kit" action is a candidate for the backlog. Make creative's two children run inside one Inngest function, so a very slow image call holds the whole run (each image call has a 120-second timeout, 0013). Words moving across every ad on a set is a deliberate difference from New picture, which changes one ad; the gallery should say "used in N ads" on Edit words and New words.
