# 0013 Spend reservations, image calls and the asset store

**Date:** 26 October 2026. **Status:** accepted (built in Sprint 5: F-21, S5-1).

**Context.** One creative run now makes about a dozen paid calls, four of them at once. Decision 0010 accepted that two calls started together could both pass the cap; with parallel image calls that is no longer a small gap. Sprint 5 also adds the first image model, the first stored files, and a vision check on every picture (Q5).

**Decision.**
- **Reserve, then call.** `generate()` and `generateImage()` check the caps and insert a `spend_reservations` row holding the call's estimate in one transaction, under two advisory locks taken in a fixed order: an app-wide one (a guest's room depends on what every workspace has spent, so the owner and guest split needs it) and the workspace's. After the call, the ledger row and the reservation's deletion share a transaction; a call that throws deletes its reservation too. Spent today is charged plus reservations under 10 minutes old, whatever day they were made (they are money about to be charged). Each check tidies its workspace's expired reservations.
- **Image calls** go only through `generateImage()` in `src/lib/models/generate.ts` (rule 5): one attempt, a 120-second timeout, no retry (a retry could pay for a second picture). The ledger gains an `images` column, and an image is charged at `IMAGE_PRICES` (Nano Banana 2.1, $0.0336 per 1K image, Q1). The prompt's few hundred input tokens are recorded but not priced, as no input price was checked for this model. A failed call is charged in full unless the provider answered 4xx (it turned the request away before drawing); a timeout, a 5xx or a reply without a picture may have been billed, so the meter may over-count a failure but never under-counts one, as with failed searches.
- **Vision input.** `generate()` takes optional pictures, sent as image file parts after the prompt, and estimates 1,600 input tokens for each. An agent definition may say which pictures go with its prompt (`images`), so a vision check runs through `runModelStep()` with its schema, one repair and its trail step, like any other model step. The picture check (`imageCheck`, Haiku) is such a definition but not a run of its own: it lives inside the Imagery workflow and is not in the run registry.
- **Image steps in the trail** are `model` steps named "Draw picture N" or "Redraw picture N", so the run page shows their model, cost and time without a new step kind. Their cost is read back from the ledger rows for the step, so trail and ledger always match.
- **Pictures are saved as they are drawn**, as WebP assets, then checked. A picture the check says has text is marked discarded and redrawn once; a second "yes" drops it, and the run output and the "Save the pictures" step list it. A picture that couldn't be checked (the cap, a provider error) is discarded too (rule 8: no unchecked picture is kept). With the cap reached mid-run, the pictures already drawn and checked are kept and the run ends `stopped_cap`.
- **The asset store** (`assets`) gives every asset a brand (logos belong to a brand, and F-10 needs that), an optional campaign and run, a `simulated` flag for pictures from the mock model (rule 1, so the gallery can label them) and a small `meta` (picture number, attempt, idea, prompt, brief version). It is append-only: authenticated users may update only `discarded_at` (a column grant), and a guard trigger refuses any other change, except a deleted run clearing `run_id`. `/assets/[id]` reads through `asUser()`, answers 404 alike for another workspace's asset, a malformed id or no session, and sends `cache-control: private, no-cache` with the sha256 as its ETag, `nosniff` and a sandboxing CSP; a matching If-None-Match gets a 304 after the access check. (It first sent `private, max-age=31536000, immutable`; the Sprint 5 review, finding 8, changed that so a shared device doesn't keep a workspace's pictures after sign-out.)
- **The mock image model** draws soft palette shapes with sharp and stamps "Simulated image" in the corner from stroke paths, not a font, because the image libraries on Vercel have no fonts. It is priced like the real model, so cap tests mean something. `sharp` becomes a direct dependency (it was only Next.js's).
- **Prompt checks** reuse the Market agent's capitalised-name finder with no brand words excused, so the brand's own name and any other proper name are refused; places (the UK list and the brand's customer regions) are allowed. The brief reaches the model as JSON with the brand's name replaced by "the brand" and the market notes' names by "a named company". A palette colour is required by its exact words, made in code from the hex (`src/lib/creative/colour-words.ts`).

**Consequences.** Every paid call now waits briefly on an app-wide lock; calls are short and the lock is held only for the check and insert. A crashed call's reservation holds its estimate for up to 10 minutes. A real vision model shown a mock picture would see the "Simulated image" stamp as text; the mock pictures only ever meet the mock check. `IMAGE_MODEL` overrides the image model; the startup check now names a missing Google key.
