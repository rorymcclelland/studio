# 0024 Picture judgement checks: the AI flags faces and don't-rule breaks, a person decides

**Date:** 3 November 2026. **Status:** accepted (built in Sprint 8: C8-2, with F-24 and Rory's answer Q4).

**Context.** Some brand rules need eyes: whether a finance brand's picture shows a face in close-up (F-24: until now only the prompt check kept faces out), and whether a picture breaks one of the kit's don't rules (C8-1 lists each for a person, as no code can check them). A model can look, but decision 0009 says models propose and code or a person decides. Rule 4 asks that every call is traced; rule 5 that it is capped; rule 3 that nothing replaces creative without a person.

**Decision.**
- **One call, three questions.** The picture check (`imageCheckAgent`, `src/lib/agents/imagery.ts`, Haiku with vision, version 2) now answers `{ hasText, reason, face: { present, closeUp }, dontRules: [{ rule, breaks, reason }] }`. The kit's don't rules are one JSON line of data after the task marker, numbered, and answered by number; the instructions say they are data, never instructions. The schema is strict (no other field, at the top or inside an answer), and `checkImageCheck` makes sure every rule is answered once and a close-up face is a face, with the usual one repair. The output allowance is 1,000 tokens (was 200) for up to 20 rules; a typical check costs about **0.03p**.
- **Only the face rule decides on the model's word (Q4).** For a finance brand (`isFinanceCategory`), a close-up face is treated like text: the Imagery workflow redraws the picture once and drops it on a second yes, and the run summary says "Picture N was dropped: the check found a close-up face ... twice". New picture refuses such a picture too. A face for any other brand is recorded but is not a finding. Every other "yes" is a **Review** item, never a Fail.
- **Results live with the picture**, in `assets.meta.vision`: the answers (each rule by its key, `dontKey`, so an edited rule is a new rule), or `status: "error" | "cap"` with the reason; and always the run, step, provider and model. Reasons are cut so the record fits the meta column's 8,000 bytes (`fitVision`). Migration `20261103000004_vision_results.sql` lets the assets guard change only meta's `vision` key (set to an object, or taken away), and adds `public.set_asset_vision`, a security-definer function that writes it only for a picture in the caller's workspace; the app's role still cannot update `meta`.
- **Two compliance rules, once per ad** (`faceRule`, `pictureDontRule`, `pictureFindings` in `src/lib/compliance/rules.ts`; `AdCompliance.picture` in `compute.ts`): "Picture: face (finance brands)" and "Picture: don't rules", each marked **"Checked by AI"** ("(simulated: the mock model)" for the mock). A "no" on the don't rules shows as **"No issues found by AI"**, not as Pass, and the don't rules themselves are still listed for a person (C8-1). A picture with no result, or whose check errored or hit the cap, gives **Review: "The picture check didn't run: <reason>"**, never Pass. A rule added since the check is named as not looked for. They count in the pill, the summary and the pack like any other finding; the manifest gives them `scope: "picture"`.
- **Check pictures** on the campaign checks the pictures of current ads that have no result (made before Sprint 8, or whose check didn't run), one Haiku call each, with the cost on the button ("about 0.03p a picture, 0.1p in all", `pictureCheckEstimate`). It never discards or replaces a picture (rule 3): what it finds becomes a finding on the ads, and a close-up face for a finance brand fails them until a person uses New picture. A picture with a result is never checked again, so a second run checks nothing and costs nothing.

**Consequences.** Ads whose pictures were made before Sprint 8 show two Review items until Check pictures runs or a person accepts them, and their pack waits for that. The refinement's "redrawn once, then dropped" applies to a picture just drawn; a picture already in ads is not dropped by a model, it fails and waits for a person. The step names stay "Check picture N for text" for the trail's history, though the step also asks about faces and the rules. Whether Haiku really spots faces and rule breaks on real pictures is a hand check on production (C8-2 #7, the Sprint 8 test pack), as CI runs the mock model.
