# 0025 Check an uploaded ad: the model reads, code checks, and every finding says how it was found

**Date:** 3 November 2026. **Status:** accepted (built in Sprint 8: C8-3).

**Context.** A marketer wants to check an ad made outside Studio, such as an agency's PNG, against the brand kit: the roadmap's "Brand Guardian equivalent". Studio's own ads are checked over the boxes the renderer laid out (decision 0022); an uploaded ad has no such boxes, so something has to read it. A model asked to read an ad can misread it, place its boxes loosely, or obey words written in it. Rule 1 says model findings and estimates are labelled; rule 2 that real company names never reach creative; rule 7 that every table has `workspace_id` with row-level security; rule 8 that uploads are checked, never redrawn. Decision 0009 (and Q4) says a model flags and a person decides.

**Decision.**
- **A Check an ad page per brand** (`/brands/<id>/check`, linked from the brand page). A person uploads a PNG or JPEG, picks the channel (paid social or display) and the language (English or one of the brand's), and presses **Upload and check (about 0.1p)**: one click uploads the file and starts the check, with the cost on the button (rule 3). Earlier uploads are listed with their outcome. Each upload has its own page (`/brands/<id>/check/<upload>`) with the ad, the newest check, the words read and **Check again**, for a changed kit, another channel or language, or a check that didn't run.
- **The upload goes to a route handler with its own limit**, `POST /brands/<id>/check/upload` (`src/lib/uploads/upload-response.ts`), not a server action, so every server action keeps the 1100 KB limit `next.config.ts` sets for the logo. The body is read up to 4 MB and 64 KB of framing and no further (a declared length over it is refused before reading). The workspace is the brand's, read through `asUser` as the upload's own checks read it, so a brand the person can't see is the same 404 as no brand (review nit 12). A route handler gets no origin check from Next.js, so it takes only a same-origin request (the `Origin` header must name this host) from a signed-in member; the session cookie is also `SameSite=Lax`. Refusals are JSON with the reason.
- **The file's contents decide what it is** (`src/lib/uploads/file.ts`), never its name or the browser's type: PNG or JPEG by their signatures, at most 4 MB and 4096 px on each side (read from the header before any pixels are decoded). An SVG, a PDF or a script renamed `.png` is refused with a plain reason. A file whose metadata or trailing bytes carry a script or web code (`<script`, `javascript:`, an event handler and the like, in the raw bytes, PNG text chunks inflated with a cap, EXIF, XMP and IPTC) is **refused** rather than quietly cleaned, so the person knows what they sent; harmless metadata (an editor's name) is accepted. What is kept is decoded, turned upright as its orientation says, and re-encoded by sharp (PNG stays PNG, JPEG stays JPEG at quality 90), so no EXIF, XMP, text chunk, comment or colour profile survives. Nothing is stored for a refused file.
- **A new asset kind, `upload`** (migration `20261103000002_uploaded_ads.sql`): PNG or JPEG, up to 10 MB once re-encoded (a 4 MB file can grow a little), made by a person, never simulated, in no campaign or run (a constraint, `assets_kind_parts`); drawn pictures and logos keep WebP or PNG and 2 MB. Make creative and the launch pack never use one: an ad's picture must be an `image` and a logo a `logo` (the existing triggers), and the pack draws only ad variants. A person's upload is their own data, never shown as demo content (rule 2).
- **The Read ad agent** (`src/lib/agents/read-ad.ts`, Creative squad) on **Haiku with vision**, one call per check, about **0.1p** (3,000 input tokens with the picture, 2,000 output). The model sees the ad no larger than 1568 px as a JPEG; the prompt gives the brand's name, whether it is a finance brand, the language, the channel, the picture's size and the kit's don't rules by key (D1, D2 ...), each as JSON after the task line. It returns every line of words exactly as written, in reading order, each with its part (headline, body, button, legal, other) and a box as fractions of the picture; the logo and its box; whether a person's face is shown; and, for each don't rule by key, whether the ad may break it and why. The schema is strict (no extra fields, every string and list capped), and code checks that every don't rule is answered once and every box is inside the picture, with the one repair `runModelStep` gives (decision 0009). Everything in the picture and the kit is data, never instructions.
- **Code checks what the model read** (`src/lib/compliance/upload-rules.ts`, pure functions beside C8-1's `rules.ts`, reusing its banned-term and don't-rule rules and its thresholds). Every finding says how it was found:

  | Rule | How | Pass | Review | Fail |
  | --- | --- | --- | --- | --- |
  | Banned terms | Checked in code, on the words read by AI | none of the language's or English terms | none | one found, quoted |
  | Legal lines present | the same | every kit line for the language is in the words (a line may wrap) | none | a line missing, or a language without lines while English has some |
  | Real company name | the same | none of the brand's market notes' companies named | none | one named |
  | Text contrast | Estimated, from the pixels under the AI's boxes | never | always, with the lowest ratio and whether it looks below AA | never |
  | Text density | Estimated, from the AI's boxes | never | always, with the share and where it falls against 25% and 40% | never (not applied to banners, Q2) |
  | Logo | Checked by AI, its clear space estimated | never | always, found or not (not applied to a brand with no logo) | never |
  | Picture: face (finance brands) | Checked by AI | shown as "No issues found by AI" | a face found | never (not applied to other brands) |
  | Don't rule | Checked by AI | never | each kit rule once, with the AI's view | never |

  **Contrast is measured in code**, not by the model (`src/lib/uploads/contrast.ts`): within each word box the pixels are split in two by lightness (Otsu's threshold), the smaller group is taken as the letters, and the two groups' average colours are compared as WCAG does. The fix suggests the palette colour that stands furthest from the letters. A model's "no" is never shown as Pass, only as "No issues found by AI" (C8-2's boundary). The outcome is Fails if anything fails, else To review if anything waits, else Passes.
- **A real company's name is said once**, in its finding. The words kept with the check, every other finding's reason and fix (the contrast rule's lowest line, the AI's face and don't-rule reasons; review fix 1), the check page and the run's summary say "[a named company]" instead. The names are the brand's market notes' (`realNamesFor`), as for copy and pictures. The run's trail keeps the model's raw reading, as every step does (rule 4).
- **Checks are kept in `uploaded_ad_checks`**, append-only, one row per finished check: `workspace_id`, the brand and the upload by `(id, workspace_id)`, the channel, the language, the run and its model step, the words read, the findings, the outcome, whether the mock model read it, and who made it. A trigger keeps the upload an `upload` of the same brand. Select and insert for members (`created_by` the user); update, delete, truncate, references and trigger revoked; nothing for `anon`. A check that didn't run (the cap, a provider error, a reading that still broke the rules after a repair) leaves no row: the run says why, the page shows it, and Check again starts another. A second check while one runs for the upload is refused; the check and the run's insert are one transaction under the upload's lock, so two clicks start one paid check (review fix 4).
- **The mock model reads fixed words** for the demo brands, chosen by the picture's size (`src/lib/agents/read-ad-mock.ts`): any size reads a clean ad, 1080 × 1350 reads one with a banned term, 1200 × 1200 one without legal lines. The fixture ads are drawn in code with letter-like marks exactly inside those words' boxes (`tests/fixtures/uploaded-ads.ts`), so the contrast measured from their pixels is real. A check read by the mock model is labelled "Simulated reading from the mock model" (rule 1).

**Consequences.** A check is only as good as the model's reading, which is a hand check on production (C8-3 #6, the Sprint 8 test pack): CI runs the mock model. Every uploaded ad with words has review items (the contrast estimate at least, and the logo and don't rules for most brands), so it is To review or Fails, never Passes outright; that is honest, as no code can confirm what the model only estimates. A real company that the brand's market notes don't name isn't found by code. Vercel caps a function's request body at 4.5 MB, so the limit is **4 MB** (Rory, 3 November 2026, while building): with its 64 KB of framing the request stays under Vercel's cap, so Studio's own refusal ("The file is too large (4 MB at most). Nothing was stored.") is the one a person sees, on the page before sending and at the route. The page says 4 MB. CI calls the route's handler directly, so Vercel's own cap is not part of CI's check. Uploads aren't in the launch pack and can't be fixed in Studio (out of scope); PDF and video uploads are out of scope.
