# 0021 Sign-off from a demo page built from CI's browser tests

**Date:** 2 November 2026. **Status:** accepted (Rory's working agreement, adopted for Studio on 2 November 2026; the pipeline built on `sprint-7-demo`).

**Context.** Until Sprint 7, a sprint was closed with a Markdown and PDF test pack (`docs/testing/sprint-N-test-pack.*`) that Rory worked through by hand on the live site. Most of what he checked was already exercised by Playwright and Vitest in CI, so he repeated work a machine had done, and a test pack couldn't say which of its steps had actually been run in the build that shipped. Rory has agreed a working agreement for his builds: Claude is the QA team, and he signs a sprint off from a demo page built from CI's browser-test results, as he would from a QA team's sprint review.

**Decision: the working agreement for Studio.**
- **Rory is the product manager:** he owns the why, the what and the sign-off. **Claude is the lead engineer and also QA**, platform and release engineering, and technical writing.
- **Every agreed case says how it is checked:** a browser test (Playwright), another CI check (a named Vitest test or a CI job), or by hand, with the reason it can't be automated. Every case is in `tests/e2e/cases.ts`. Hand checks are only for what can't be automated.
- **An independent QA agent** (one that did not build the work) reviews the tests against the agreed cases, and an independent reviewer checks security and correctness, before the demo.
- **Rory signs off from the demo page.** A case shows Passed or Failed only from a browser test that actually ran in that build. Anything not automated says so and is never shown as passed.
- **The live site changes only after sign-off.** Merging to `main` deploys production, so the merge, and the live database migrations with it, waits for Rory's sign-off and his approval of the deploy.
- **The Studio exception.** CI runs the mock model and has no real keys (rules 5 and 6), so anything that needs real AI output (translation quality, crops on real 2K pictures, picture and copy quality) is a hand check on production after the deploy, sent to Rory as a Markdown test pack in `docs/testing/`.

**How the pipeline works.**
1. **The case list.** `tests/e2e/cases.ts` lists every agreed case by sprint (`sprint`, `story`, `id` such as `C7-1.3`, the case in a few words) with its checks: `{ kind: "browser", spec, title }`, `{ kind: "ci", file, test }` or `{ kind: "ci", job }`, and `{ kind: "hand", why }`. A case may have several (a browser test for what a person sees, a Vitest test for another workspace or a forced failure, a hand check for real AI output), and a `note` says what a check does not show. `tests/lib/cases.test.ts` checks that every browser check names a spec and test that exist and carry the case's annotation, and that every CI check names a Vitest file that exists with that test or describe title in it.
2. **Tagged browser tests.** Each Playwright test that shows a case carries `{ type: "case", description: "<id>" }` in its annotations. The demo page matches results to cases by that annotation, on the test the case list names, so an untagged test, or a tagged test the list doesn't name, counts for nothing.
3. **Recordings with captions.** In CI (or locally with `E2E_VIDEO=1`) Playwright records every test at 1280 × 720 (`playwright.config.ts`); traces are kept on failure as before. Tests name their steps in plain English (`step()` in `tests/e2e/helpers.ts`, a `test.step` that also sets a caption), and the caption is drawn along the bottom of the page in a closed shadow root, so no locator, text search or contrast check sees it and it takes no clicks.
4. **Results to a branch.** Playwright also writes a JSON report (`playwright-report/results.json`). The first CI job writes Vitest's JSON results and passes them on as an artefact. After the browser tests, whether they passed or failed (not when the run was cancelled), on pushes only, the e2e job runs `scripts/e2e-results.mjs`, which gathers into one folder the report (with the recordings' paths made relative and every other path dropped), the last attempt's recording of each case-tagged test, the slimmed Vitest results and `run.json` (run id and link, commit, branch, date, and the first job's result). The job then pushes that folder as **one orphan commit, force-pushed, to `e2e-results/ci/<source branch>`**, so the branch holds only the latest run. The commit is made through a separate index, so the checkout is untouched; the e2e job alone has `contents: write`. CI ignores pushes to `e2e-results/**`. It goes to a branch because a cloud session can't download Actions artefacts but can fetch a branch.
5. **The demo page.** `node scripts/demo-page.mjs --results <checkout of the branch> --sprint N --out <folder>` writes one self-contained `index.html` with the recordings beside it in `videos/` (referenced relatively, so the folder can be published as it is), and the same case table as Markdown to `docs/testing/sprint-N-demo.md`. The page has the run, commit, date and totals, the sprint goal from the refinement, then each story's cases in order, each with one of: **Passed** (every browser test the case names ran and passed; "Passed on a retry" when it took CI's one retry), **Failed**, **Not run** (no tagged browser test ran, or it was skipped), **Passed in CI** or **Failed in CI** (no browser test, and the run's Vitest results show the named tests), **CI check** (named, with no result claimed because the run has none for it) or **Hand check** with the reason. A case with a browser test and a hand check shows both, so the hand check is still visibly to do. A local run's page says "Local run (not CI)" in its header.

**Honesty labels.** The recordings run against the mock model, so every picture and every word the AI would write in them is simulated, and the brands are fictional (rules 1 and 2); the page says so. No em dashes, British English.

**Sprint 7.** Sprint 7 was deployed to production on 2 November 2026, before its demo existed, with Rory's approval of the deploy. Its demo page is built after the fact from the `sprint-7` branch's CI run, and its hand checks (translation quality and crops on real pictures on production, F-28's week of logs, and N-7a after 12 November) stay open until done. **From Sprint 8, merges to `main` wait for Rory's sign-off from the demo page.**

**Consequences.** Each push of a branch stores its latest recordings in the repository: a few minutes of video for each case-tagged test, a few megabytes each. Force-pushing leaves the previous run's objects unreferenced until GitHub collects them; if the repository grows noticeably, the recordings can move to a size-capped store. Recording every test makes the e2e job a little slower. The results branch is only as fresh as the last push that reached the e2e job: when the first job fails, the browser tests don't run and the branch keeps the previous run, whose `run.json` names its commit, so the page never passes off an older run as the current one. A pull request's run pushes nothing (its branch's push already did). A case list that drifts from the specs fails `npm test`.
