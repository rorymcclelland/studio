# 0010 Public address: invite links, per-workspace caps, and real names in market notes

**Superseded in part, 28 October 2026:** invites now start Studio's own session instead of using Supabase's admin API, invitees can sign back in by email, and previews use the Neon `preview` branch instead of a second Supabase project (decision 0015). The invite links, allow-list, spend limits, rule 2 wording and after-deploy sync stand.

**Date:** 26 October 2026. **Status:** accepted (built in Sprint 4: F-3, F-8, F-15, S4-3).

**Context.** Demo gate 1 puts the app on an address interviewers can open. Supabase's built-in email only delivers to members of the project's team (2 an hour), so magic links can't reach interviewers, and Rory chose not to set up an email service. Each interviewer must not be able to run up the AI bill or use Rory's share of it. And the Market agent's notes are only useful if they can say which real company did what, which rule 2 forbade.

**Decision.**
- **Invites by link.** The owner (`OWNER_EMAIL`, else the first `ALLOWED_EMAILS` entry) creates an invite on /invites; the app shows a one-time link (`/invite/<token>`, 32 random bytes, only its SHA-256 stored, 7 days) for him to send himself. Opening the link shows a Continue page; the invite is used only on that POST, so link previews and email scanners can't use it up. The server action signs the person in through Supabase's admin API (`SUPABASE_SECRET_KEY`, server only): create the user if needed, mint a one-time sign-in and verify it at once, so no email is sent.
- **The allow-list** is `ALLOWED_EMAILS` plus a used, unrevoked invite (`public.is_invited`). Revoking an invite revokes the person (every invite for that email), and they are signed out on their next page load. Allow-listed addresses can't be invited (a link would let its holder into that account).
- **Invites are app-level**, like profiles: no `workspace_id`, readable and writable only by their creator, and redeemed through two narrow security-definer functions (`check_invite`, `use_invite`) because the person redeeming isn't signed in. Only the owner can create one: the app checks, and the Data API is off; the insert policy itself does not know who the owner is (accepted).
- **Spend.** The owner may use the whole daily cap (`DAILY_CAP_PENCE`, £1). Every other workspace has its own daily limit (`WORKSPACE_DAILY_CAP_PENCE`, 50p) and can never use the owner's reserve (`OWNER_RESERVE_PENCE`, 50p) while he hasn't spent it. The spend meter shows each person the limit that applies to them. Two runs started at the same moment can both pass the check (bounded by one call's estimate each); accepted.
- **Web search** goes through `generate()`: the estimate adds the search allowance (5) at the price in `src/config/prices.ts` (Anthropic launched at $10 per 1,000; re-check), the ledger records searches made, a search call is not retried and gets 180 seconds, and a call that fails after searching is charged the full allowance so the meter never under-counts.
- **Rule 2, reworded.** Market notes may name real companies, with their sources. Every capitalised name in a note that isn't a place, a date or the brand's own words must be declared; the brief sees the notes with declared names replaced ("a named company") and its checks refuse any declared name. Source titles and domains are kept out of the text the brief sees.
- **Previews** use a second free Supabase project for data and sign-in, with the mock model forced, so they never touch production data or spend.
- **After each production deploy** a GitHub Action asks the app to sync its functions with Inngest and checks the health endpoint lists `agent-run`.

**Consequences.** An invitee whose session ends needs a new invite (no email to send them a link); an email service can replace this later (backlog). Interviewers start in an empty workspace and add the demo brands themselves. The name check can make the Market agent declare a harmless capitalised word, which only keeps that word out of briefs.
